    2. Die Ausführungsumgebungen von VBSCRIPT

    2.1. Einleitung

    Ein vbscript-Programm wird nicht direkt unter Windows ausgeführt, sondern in einem Container, der ihm einen Ausführungskontext und eine Reihe von ihm eigenen Objekten bereitstellt. Darüber hinaus kann das VBScript-Programm Objekte nutzen, die ihm vom Windows-System zur Verfügung gestellt werden; diese Objekte werden als ActiveX-Objekte bezeichnet.

    In diesem Dokument werden wir zwei Container verwenden: den Windows Scripting Host, der gemeinhin als WSH bezeichnet wird, und den Internet Explorer, der im Folgenden manchmal als IE bezeichnet wird. Es gibt noch viele weitere. So sind beispielsweise die MS-Office-Anwendungen Container für eine Ableitung von VB, die als VBA (Visual Basic for Applications) bezeichnet wird. Darüber hinaus gibt es zahlreiche Windows-Anwendungen, die es ihren Benutzern ermöglichen, die Grenzen des Betriebssystems zu überwinden, indem sie Programme entwickeln können, die innerhalb der Anwendung ausgeführt werden und deren spezifische Objekte nutzen.

    Der Container, in dem das VBScript-Programm ausgeführt wird, spielt eine entscheidende Rolle:

    • Die Objekte, die dem VBScript-Programm vom Container zur Verfügung gestellt werden, unterscheiden sich von Container zu Container. So stellt WSH einem VBS-Programm ein Objekt namens WScript zur Verfügung, das beispielsweise Zugriff auf die Netzwerkfreigaben und -drucker des Host-Rechners gewährt. IE hingegen stellt dem VBS-Programm ein Objekt namens document zur Verfügung, das das gesamte angezeigte Dokument HTML repräsentiert. Das VBS-Programm kann dann auf dieses Dokument zugreifen. Excel stellt einem Programm namens VBA Objekte zur Verfügung, die Arbeitsmappen, Arbeitsblattseiten, Diagramme usw. darstellen – also alle Objekte, die von Excel verarbeitet werden.
    • Auch wenn die Objekte eines Containers einem VBScript-Programm seine volle Leistungsfähigkeit verleihen, können sie manchmal bestimmte Bereiche einschränken. So kann ein im Browser ausgeführtes VBScript-Programm IE aus Sicherheitsgründen nicht auf die Festplatte des Host-Rechners zugreifen.

    Wenn also von VBScript-Programmierung die Rede ist, muss angegeben werden, in welchem Container das Programm ausgeführt wird.

    Unter Windows ist VBScript nicht die einzige Sprache, die in den Containern WSH oder IE verwendet werden kann. Man kann beispielsweise JScript (=JavaScript), PerlScript (=Perl), Python usw. verwenden. Viele dieser Sprachen scheinen auf den ersten Blick VBScript überlegen zu sein. Letzteres hat jedoch einige wesentliche Vorteile:

    • VB und seine Varianten VBSCRIPT und VBA sind auf Windows-Rechnern weit verbreitet. Kenntnisse dieser Sprache scheinen unverzichtbar zu sein.
    • Es sind eher die Objekte, die ein Programm nutzen kann, als die von ihm verwendete Sprache, die seine Leistungsfähigkeit ausmachen. Viele dieser Objekte werden jedoch von den Containern bereitgestellt und nicht von den Sprachen selbst.

    Ein Nachteil von VBSCRIPT ist, dass es nicht auf andere Systeme als Windows, beispielsweise Unix, übertragbar ist. Seine Konkurrenten JavaScript, Perl und Python sind dies hingegen. Wenn man auf heterogenen Systemen arbeiten muss, kann es interessant oder sogar unerlässlich sein, auf den verschiedenen Systemen dieselbe Sprache zu verwenden.

    2.2. Der Container WSH

    Der Container WSH (Windows Scripting Host) ermöglicht die Ausführung von Programmen, die in verschiedenen Sprachen geschrieben sind – darunter VBScript, JavaScript, PerlScript, Python usw. –, innerhalb von Windows. Damit eine Sprache in WSH verwendet werden kann, muss ein bestimmter Standard eingehalten werden. Jede Sprache, die diesen Standard erfüllt, kommt für die Ausführung in WSH in Frage. Es ist denkbar, dass sich die oben genannte Liste der in WSH ausführbaren Sprachen noch erweitern wird. Ein Container stellt den von ihm ausgeführten Programmen Objekte zur Verfügung, die ihnen ihre eigentliche Leistungsfähigkeit verleihen. Dies trägt dazu bei, die Unterschiede zwischen den Sprachen zu verwischen, da sie dann alle denselben Satz an Objekten verwenden. Die Entscheidung für eine bestimmte Sprache anstelle einer anderen kann somit eher eine Frage des Geschmacks als der Leistung sein.

    Die Ausführung eines Programms in WSH erfolgt mithilfe von zwei ausführbaren Dateien: wscript.exe und cscript.exe. wscript.exe befindet sich normalerweise im Windows-Installationsverzeichnis, das üblicherweise %windir% heißt:

    
C:\ >echo %windir%
C:\WINDOWS

C:\>dir c:\windows\wscript.exe
WSCRIPT  EXE       123 280  19/09/01  11:54 wscript.exe

L'exécutable cscript.exe se trouve lui sous %windir%\command :

C:\>dir c:\windows\cscript.* /s

Répertoire de C:\WINDOWS\COMMAND
CSCRIPT  EXE       102 450  26/06/01  17:49 cscript.exe

    Das „w“ in wscript steht für windows und das „c“ in cscript steht für console. Ein Skript kann wahlweise mit „wscript“ oder „cscript“ ausgeführt werden. Der Unterschied liegt in der Art und Weise, wie Meldungen auf dem Bildschirm angezeigt werden:

    • wscript zeigt sie in einem Fenster an
    • cscript zeigt sie auf dem Bildschirm an

    Wir halten folgende Punkte fest:

    1. Der Container WSH ist nicht an eine bestimmte Sprache gebunden. Ein WSH-Skript kann verschiedene Sprachen in einer Datei mit der Endung .wsf mischen
    2. Das Skript wird dann von den Tags <job id="..."> ... </job> umschlossen
    3. Innerhalb der Anwendung (=Job) werden die von den verschiedenen Codeabschnitten verwendeten Sprachen durch die Tags <script language="...."> .... </script> gekennzeichnet
    4. Diese Auszeichnungssprache hat einen Namen: XML für eXtended Markup Language. XML definiert keine Tags, sondern Regeln für die Anordnung von Tags. Hier müsste man also sagen, dass die in einem WSH-Skript verwendete Auszeichnungssprache dem Standard XML entspricht.

    Im weiteren Verlauf werden wir in .vbs-Dateien ausschließlich VBScript verwenden.

    2.4. Das Objekt WSCRIPT

    Der Container WSH stellt den von ihm ausgeführten Skripten ein Objekt namens wscript zur Verfügung. Ein Objekt verfügt über Eigenschaften und Methoden:

    Ein Objekt Obj verfügt über Eigenschaften Pi, die seinen Zustand festlegen. So kann ein Objekt thermomètre eine Eigenschaft température haben. Diese Eigenschaft ist einer der Aspekte des Zustands des Thermometers. Ein weiterer Aspekt könnte die maximale Temperatur Tmax sein, die es aushalten kann.

    Das Objekt Obj kann Methoden Mj besitzen, die es externen Akteuren ermöglichen, entweder:

    • seinen Zustand abfragen
    • seinen Zustand zu ändern

    So könnte unser Thermometer, sofern es elektronisch ist, eine Methode allumer haben, die es einschaltet, eine weitere éteindre, die es ausschaltet, und eine weitere afficher, die die Gleichgewichtstemperatur anzeigt, sobald diese erreicht ist. In der Programmierung ist eine Methode eine Funktion, die Argumente entgegennehmen und Ergebnisse zurückgeben kann.

    In VBScript werden die Eigenschaften Pi eines Objekts Obj als Obj.Pi und die Methoden Mj als Obj.Mj bezeichnet. Das Objekt „wscript“ von WSH ist ein wichtiges Objekt für die Methoden, die es den Skripten zur Verfügung stellt. So ermöglicht beispielsweise seine Methode echo die Anzeige einer Meldung. Die Syntax dieser Methode lautet wie folgt:

    wscript.echo arg1, arg2, ..., argn

    Die Werte der Argumente von argi werden dann in einem Fenster (Ausführung über wscript) oder auf dem Bildschirm (Ausführung über cscript unter DOS) angezeigt.
